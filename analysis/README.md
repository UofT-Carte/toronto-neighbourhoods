# Neighbourhood agreement analysis

Preliminary analysis of crowdsourced neighbourhood submissions across a
name-agreement × shape-agreement grid.

## Run (one command)

```bash
npm run explore     # fetch → analyse → launch the dashboard
```

That pulls a fresh snapshot, regenerates the report/CSVs/map data, and serves
the submissions dashboard (`/`) and the agreement heatmap (`/heatmap`) at
http://localhost:4321.

The pieces are also available on their own:

```bash
npm run analysis          # fetch + analyse, no dashboard
npm run analysis:fetch    # dump analysis/data/snapshot-YYYY-MM-DD.json
npm run analysis:analyze  # write analysis/out/report-YYYY-MM-DD.md + CSVs + viz/
npm run dashboard         # serve the last generated output (no re-fetch)
```

The fetch needs application-default credentials for the Firebase project
(`gcloud auth application-default login`), same as the dashboard.

## Tuning

All thresholds are in the config block at the top of `analyze.py`
(`NAME_SIM_THRESHOLD`, `GRID_RES`, `MIN_MEMBERS`, `IOU_THRESHOLD`, area bounds).

## Name relations

`analyze.py` also emits `out/relations-<date>.csv` — which neighbourhood **names**
refer to the same ground, which are nested, and which are merely neighbours.

Two independent evidence channels, never fused into one score:

- **Declarations** (`otherNamesText`) generate candidate pairs. High recall,
  **low precision**: roughly half of what people offer as an "other name for this
  area" is actually the name of the place *next door*. The Annex ~ Seaton Village
  was declared by 7 people and shares essentially no ground.
- **Geometry** adjudicates them, using medians over cross-pairs of **raw drawings**
  (never over aggregated footprints, which manufacture fake containment).

There is **no clustering anywhere** — the pair is the unit of analysis, so nothing
can chain. Verdicts are **effect sizes with a bootstrap stability gate**, not
significance tests: a significance test's answers would invert at the 10,000
submission target purely from growing statistical power.

### What it will not tell you

- **It never says "alias" or "subset".** That is not identifiable from this data —
  the human-*declared* alias (The Village / Church-Wellesley) is geometrically
  **more nested** than the nominal sub-area (South Parkdale / Parkdale). It reports
  the geometric fact (`SAME_EXTENT` / `NESTED` / `OVERLAPPING` / `DISTINCT`); you
  supply the noun.
- **`UNDETERMINED` is the biggest bucket, and that is correct.** It doubles as a
  recruitment list: exactly which neighbourhoods need more drawings before the
  question can be answered at all.
- **Generic head-nouns only count as standalone answers.** "The Village", "The Beach"
  and "Downtown" are keyed by their bare noun, so they are only matched when someone
  offers them *as* the answer — not mid-prose and not inside a longer name. This is
  what stops "Guildwood **Village**" and "Sugar **Beach**" from fabricating
  declarations nobody made, but it also means an in-prose mention ("some call it the
  Beach") is missed, and "The Gay Village" is not resolved to The Village.

Thresholds live in `REL_CFG` in `analyze.py`. `merges.yaml` holds hand-curated,
name-only cluster merges (no geometry, so not circular).

## Output

- `out/report-*.md` — the human-readable report (Q1 consensus, Q2 contested
  boundaries + solid-core/fuzzy-edges, Q3 contested turf).
- `out/clusters-*.csv` — per-cluster shape metrics.
- `out/contested-*.csv` — cross-name overlap pairs.
- `out/viz/` — per-neighbourhood GeoJSON + `index.json` for the interactive map.

## Interactive heatmap

`analyze.py` also writes the map data to `out/viz/`. To explore it:

```bash
npm run explore     # or `npm run dashboard` to skip re-fetching
# then open http://localhost:4321/heatmap
```

Pick a neighbourhood from the sortable panel — sort by `core/union` ascending
to find the most-contested, descending for the most-agreed. The map shows what
share of that neighbourhood's hand-drawn boundaries covers each 50 m block,
with the 50% and 75% agreement contours and the most-agreed point. Hover any
block for its exact figure; tick "show individual drawings" to see the raw
submissions.

The map is generated by the same code as the report, so its numbers always
match `clusters-<date>.csv`.

### Contested locations — one name, two places

A name whose drawings split into **two coherent groups that share essentially no
ground** is not "low agreement" — it is **two places under one name**. Select such a
neighbourhood and the map shows the two camps side by side in contrasting colours
instead of blending them into one misleading surface.

`Queen west` is the clear case: 9 drawings around Spadina/John (the Fashion-District
stretch) and 4 around Trinity Bellwoods, 1.8 km apart, sharing almost no ground.

Detection deliberately does **not** use silhouette, which is dominated by outlier
drawings and ranks a 2-vs-31 peel above the one genuine 4-vs-9 split. The test is a
**balanced** split whose halves are **near-disjoint** *and* **not nested** — a small
camp sitting inside a big one is a *scale* disagreement about one place, not two
places, and IoU alone cannot see that (a small polygon inside a large one has low
IoU while sharing all of its ground). Thresholds are in `CAMP_CFG` in `analyze.py`.

### Relations panel

Selecting a neighbourhood also lists what the name-relations analysis knows about it
— same ground / nested / declared-but-actually-neighbours — each with the verbatim
quote that produced it. Click one to jump to it.
